                    Turbo Newscan finally goes public!
                    ==================================

Finally, after almost a year of beta-testing, TN hit the nets on 4-8-94.
From coast to coast, more and more boards are starting to use TN as their
/X newscan replacements!

Although there are still a few small bugs to iron out in the release
version, it is fairly stable and a very worthwhile addition to any /X
board.

To some, it is TN's flagging method that appeals them, to others, it is
the almost instantaneous scan times. Whatever the reason, TN will be
around for a really long time!

                TN is what amiEXPRESS is all about: speed!



                               Registration
                               ============

1. How do I register?

As of 4-10-94, the registration fee has not been set, but will be in the
range of $25 to $30 US. The fee will include unlimited technical support
with me, the author, via the WHQ TN bbs or Internet, a frequent TN
newsletter, an official custom version with user's name/handle/bbsname,
and of course additional features not found in the public version.  A
100% cotton t-shirt with the Turbo Newscan logo will be available for an
additional charge.

Registered users will also get a sneak preview peek at the newest Turbo
Zippy which will be identical to TN in functionality, plus it will search
at almost twice the speed of the old TZ.

It has not been decided whether future updates will be free or not. Users
will be told, in writing, exaclty what features they will be getting for
their money at the time of the transaction. I'm not here to rip anyone
off, just to make a few honest bucks to pay for books and school.

It is also important that *before* you register, you have thouroughly
tested TN in your system and made 100% it doesn't crash in any way.  Some
A4000 /X 3.xx systems have been known to freeze while multiple users
accesed TN at the same time.

Basically, all sales are final and no refunds will be given. I hate to put
it so bluntly, but in practice I think you will be very happy with the
product and I will work with you if there is ever any problem.

Then there is the matter of US export laws...  So until I figure out how
they work, registration will be available to United States users only.

Maybe there will be a European version?

A more formal contract with all the little details will be given at a
later time.

Again, the registration date and price has not been set.  In fact, I
haven't finished coding the registered version.  I expect it will be ready
by late May 1994, so please hang in there for a few more weeks.  Finals
are coming!


                   TN FAQs (Frequently Asked Questions)
                   ====================================

1.  I get this "code under construction" banner sometimes; it fills up my
screen and is very annoying.  Can you fix this bug please?

Actually, it's not a bug. It is my version of a "Delay Screen" for
unregistered users. The registered version does not have this 'bug'.


2. Can you add a nuker to the [s]ysop commands? It would be really great!

I am working on it as fast as I can! Fortunately, I have the code for the
Ax-Edit nuker, so it's just a matter of porting it over.  Maybe May 1994.

3.  I really like your tool, but CTRL-C doesn't work, and the scrolling is
pretty slow!

Yeah, the scroller in the public version is not optimized at all.
Registered version will have faster output and better CTRL-C checking.

The CTRL-C checking is taking place, but the scroller is going too fast to
see it! You can fix this by setting your "[s]croll speed" setting to 1 or
higher. This will set an AmigaDOS Delay() command and give my routine a
chance to catch your keystrokes. Future versions will tap into the serial
port directly and read any input.


4. I like the cursor flagging method, but sometimes I want to go back a
page or two, but it simply wraps to the bottom...

Well, what you are asking is a virtual scroller, and that's one tough sob
to code! For the time being, use "[m]anual flags" when wanting to flag
something outside the current screen. I will try to code the virtual
scroller, but it probably won't be ready till Summer 1994.


5. Can you make TN /X 3.xx user friendly? I had to make NDIRS and PATHS
files all over the place! /X 3.xx has icons for that.

If there is enough demand for it, I will, but otherwise I consider reading
incons a waste of code.


6. The other day two people accessed TN at the same time (different nodes)
on my /X 3.xx bbs and I got a system requester.  Something about a
PIPELINE error?

I'm not sure what's happening there... If you can give me more info on the
requester I will try to figure out what's going on. Maybe you could try
asking the /X people? Because this error only seems to occur in 3.xx
versions.

7. The [d]ownload command doesn't seem to be working.

Hmm.. strange.. I will take a look at the code and see if any changes were
made to prior versions.


7. Whos the girl on the picture MACKSTER.HAM?

She's an old girlfriend from Mexico City, my home town. Her name is Marta

                        C Optimization: Lesson #1
                        =========================

In this issue, I discuss some important optimization techniques that you
can use in your programs. We will build a utility that will tell us how
many blocks are free on any AmigaDOS device.

The first thing every program has to do is initialize itself to avoid
problems down the line. Mainly arrays. Here is a very quick and small way
to accomplish this:


char out[80], *p;
for (p=out; p<&out[80]; p++)
  *p=NULL;

By using a pointer *p instead of an index (out[x]), we save 80
multiplication instructions because we are accessing the memory directly.
The output code is very small too.

Now lets look at sending text to the CLI window. By using a Write()
function instead of a printf(), your program will be about 2k smaller!

#include <proto/dos.h>
Write(Output(), "\nMcFree v2.1 by Mack Lifeguard\n\n",32);

This function is very fast and takes up only a few hundred bytes. You can
make it dynamic like this:

Write(Output(), out, strlen(out));

The device "Output()" is your current CLI window.


Since we are not using any C memory allocation or file I/O, we can use the
smaller exit() function, which is:

_exit(0);    /* Always exit with 0 on success. */

Notice the "_" underscore! This _exit() behaves exactly like the regular
exit(), but doesn't free any C memory or close files.

Ok, take a look at MCFREE21.LHA, included in this archive, for the
complete source and executable, which is only 1688 bytes!
