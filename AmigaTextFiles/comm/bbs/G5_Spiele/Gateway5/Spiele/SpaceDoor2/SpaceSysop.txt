WHAT IS SPACEDOOR?
~~~~~~~~~~~~~~~~~~
  SpaceDoor is an online game written for DLG, the very best BBS for
the Amiga :)  SpaceDoor is a multi-player, sector based game. It
involves a little trading, a little battle, and a little luck. If you
more information on what the game is like, then you will have to read
the player instructions and play the game!

  Please read this entire file before attempting to install and run
SpaceDoor. There are things you must do, and things you must not do,
so reading this entire file first could save you a lot of grief.

  I also recommend reading the SpacePlayer.txt file before changing
any of the default player settings.

  To play SpaceDoor, the user must have a screen at least 78 characters
wide, and their terminal must support ANSI screen positioning.

  Please forgive any errors in this text file, I typed it up in a
hurry, and my typing isn't that good.

SETTING IT UP
~~~~~~~~~~~~~
  Ok, here are step by step instructions for setting up SpaceDoor. I
will assume that all the files from the archive are in a seperate
directory, by themselves.

[1] Create a directory to hold Spacedoor. For example:
      makedir dh0:dial/doors/spacedoor

[2] Edit your startup-sequence or dialog.start script to assign
    Space: to the directory you created above. The command to do
    this could be:
      assign Space: dh0:dial/doors/spacedoor/

[3] So you won't have to re-boot to execute the above assign
    (the Space: assignment must have been executed for you
    complete the set-up), execute the same assignment from the
    CLI:
      assign Space: dh0:dial/doors/spacedoor/
    You won't have to do this if you re-boot instead.

[4] CD to the directory where you un-archived the SpaceDoor files,
    for example:
      cd dh0:download/

[5] Copy all of the files to Space:
      copy #? Space:

[6] Execute the sysop's SpaceDoor editor (SpaceEd):
      Space:SpaceEd

[7] A couple of title screens will appear, then SpaceEd will ask
    you how many players and sectors you want. Good numbers to
    start with are 50 players, and 1000 sectors. This would
    create a 4590 byte player data file, and a 49000 byte sector
    data file. The data files will be created, when they are done,
    a menu will appear.

[8] Exit SpaceEd. We will come back to it later. (See CUSTOMIZING
    SPACEDOOR).

[9] Create a menu entry in DLG for SpaceDoor. The ONLY options it has
    been tested with are given below, I strongly suggest you stick
    to these:

     Please enter the name of the executable:  space:SpaceDoor "%1"

     Does executable require DIALOG to reload
     the menu when finished [Y/n] => Yes

     Please enter handler flags:
       Enable CTRL-c breaking [y/N] => No
       Enable CTRL-d breaking [y/N] => No
       Enable carriage return/linefeed [Y/n] => Yes
       Enable echo [y/N] => No
       Enable process killing [Y/n] => Yes
       Enable kill pending [Y/n] => No
       Enable pass-thru mode [y/N] => No
       Enable pausing [y/N] => No
       Enable raw mode [Y/n] => Yes
       Enable timeouts [Y/n] => Yes
       Enable verbose pause [y/N] => No
       Enable line freezing [y/N] => No

You can, of course, select whatever you want for a user level.

[10] Create a menu entry to allow your users to read the instructions
     (the file SpacePlayer.txt, which should now be in your Space:
     directory). Use the DLG command DF for this, see your DLG
     instructions for the flags to set.

[11] SpaceDoor should be ready to run! You should now log in locally
     and test it, just to make everything is working.

  If you don't want to customize SpaceDoor, then you don't have to
do anything else. The default settings will be used for new and system
players. However, if you want to make changes, read on. Please read
the SpacePlayer.txt file before making changes, that way you will know
what you are changing!


CUSTOMIZING SPACEDOOR
~~~~~~~~~~~~~~~~~~~~~
  First, a word of warning. When I started writing SpaceDoor, I didn't
know what I wanted the game to do (I still don't), so I first wrote the
editor, then made the game up as I went along. So, some of the things
in the editor might not correspond to things in the game. Additionally,
it is possible to confuse the game if you change things that I tell you
not to. Also, make sure nobody is playing the game while you are
editing or re-creating the data files!!! YOU HAVE BEEN WARNED!!!

  To begin, run SpaceEd again. After the title screens, you will
see a menu:

        [P] Edit Players               [S] Edit Sectors
        [E] Extras                     [C] Create Files
        [Q] Quit

[Q] Quit will exit SpaceEd.
-------------------------------------------------------------------------
[C] Create Files will re-create all of your data files, use this when you
wish to reset the entire game. The old data files will be deleted, as
will all player message files (those starting with SD- ).
-------------------------------------------------------------------------
[E] Extras will create simple reports and statistics on players and
sectors. Output is sent to the file of your choice.
-------------------------------------------------------------------------
[P] Edit Players is a big one. There are two types of players in
SpaceDoor: system players (numbers 0 to 5) and user players (numbers
6+). Player 0 is the new player, it is used to hold the settings for
new players when they join the game. Thus, by changing player 0, you
can change what new players get when they first enter the game.
Changing the other system players will affect all of the players of
that type throughout the game. For example, by default, the Pirate
is a fugative, so if a player destroyed a pirate anywhere in the game,
he will collect the bounty. Or if you give the Police player
military weapons etc, then all Police ships in the game will get these.

You may wish to edit the New player so that your users will not have
to work so hard starting outt. You may give them extra holds, better
equipment, more cash, additional possessions, etc. Or, once a player
has joined, you may edit the data for that player only (I don't
recommend this, it would be cheating).

Note that this menu is case sensitive! The edit player screen is:

Player#     Disk:0                  Input:0

[!]User         :0               [a]Handle       :New
[b]Cash         :5000            [c]Tech         :1
[d]Discoveries  :0               [e]Battles      :0
[f]Status       :Clean           [g]Times Played :0
[h]Unused       :                [i]Location     :0
[j]Fortress     :0               [k]Guard Toll   :0
[l]Option       :Defend Only     [m]Possessions
[n]Power Type   :Standard        [o]Power Level  :5000
[p]Batt Level   :0               [q]Beam Type    :Standard
[r]Missiles     :0               [s]Shield Type  :Standard
[t]Jammer       :No              [u]Guards       :0
[v]Sensor Type  :Standard        [w]Holds        :5
[x]Ship Damage  :0               [y]Turns        :50

Modify a-x or:
S = Save D = Delete N = Next L = Last P = Pick Q = Quit:

This is the new player record, but others are similar. Again, the new
player record determines what new players get when entering the game. 
I recommend that you do not give new players much more than the defaults,
let them work for anything extra. If they have too much, the game will
be too easy, and they will get bored quickly. The options on this
menu are (remember, these are case sensitive!):

[!] [a] DO NOT CHANGE THESE FOR ANY PLAYER! They are there only for
    when I was debugging the program. Changing them will confuse SpaceDoor.
[b] The amount of cash the player has (max 500000).
[c] The player's technology level (0-10). This is used by several
    things in the game.
[d] The number of discoveries the player has made (0-10).
[e] The number of battles a player has won.
[f] The players legal status (Clean, Wanted, Fugative).
[g] The number of times the player has played.
[h] Just like it says.
[i] The sector the player's ship is currently in. DO NOT CHANGE THIS
    or you will confuse SpaceDoor.
[j] The location of the player's fortress. This is not used in this
    version of SpaceDoor (remember I said that the editor didn't
    exactly match the game?). Still, you shouldn't change this!
[k] The number of credits that a player's guards will collect on
    owned sectors. The players ship will also collect this if his
    logoff option is set to.
[l] The player's logged off option. This determines wether a players
    ship will only fight to defend itself, collect a toll, or always
    fight when the player is logged off.
[m] This allows you to change the list of possessions a player has.
    A player may have up to 10 possessions. By default, new players
    get an ID Transponder, a Towel, and a Hyperwave Beacon. You may
    wish to also give them an Unknown Item, just to make things
    interesting :)
[n] Reactor type (Standard, Enhanced, Military). This determines the
    maximum amount of energy that a ship can have (under normal
    circumstances).
[o] The current amount of energy the player's ship has. Maximum is
    determined by the reactor type.
[p] Battery level. The player can use this when his energy runs low,
    or it is used automatically if a player runs low on energy in
    the middle of a battle. You may wish to change this from
    0 to 500 or so for new players.
[q] Standard, Enhanced, or Military weapon. Better weapons do more
    damage.
[r] The number of missiles the player has (0-10).
[s] Standard, Enhanced, or Military shields. Better shields resist
    damage to the ship better.
[t] Wether the player has a missile jammer or not.
[u] The number of guards the player has. Guards are deployed to own
    sectors, they will collect a toll for the player that owns them.
[v] Standard, Enhanced, or Military sensors. Better sensors provide
    more information when scanning a ship, and in battle.
[w] This allows you to change the number of holds a player has (up
    to 50), and what is in them. Please do not try to put more things
    in a player's holds than there is room for.
[x] The percent damage to a players ship. When this reaches 98 or
    higher, the player's ship is destroyed and he must start over
    from scratch.
[y] The number of turns a player has left. If a player runs out of turns,
    the date is stored here as a negative number. When he logs back in
    day, he is given a new allocation of turns, taken from the new player
    record. The maximum number of turns a player can have in one day is 99.

The options below the players record are:

S Save the record. If you don't do this, all the changes you make will
  be lost!
D Delete the current player. A seperate utility will be available in
  the future to delete old players (as will several other utilities).
N Go to the next player's record.
L Go to the previous player's record.
P Pick a record number to go to.
Q Quit to the main menu (remember to save changes first!).
-------------------------------------------------------------------------
Back on the main menu...
[S] Edit Sectors. This allows you to change the characteristics and
contents of any sector, such as it's name, port type, and items found here.
SpaceEd places different ports and objects in sectors throughout the
galaxy at random.

The menu looks like this:

Sector#     Disk:1                  Input:1
[a]In Sector    :A Government Outpost
[b]Name         :YOATOD
[c]Stuff Here   :
   None                , 0    None                , 0
   None                , 0    None                , 0
   None                , 0    None                , 0
   None                , 0    None                , 0
   None                , 0    None                , 0

[d]Ships Here   :0 0 0 0 0
[e]Owner        :0
[f]Connectors   :0 0 0 2 3 11

Modify which a-f or s = Search Ship o = Search Owner
S = Save N = Next L = Last P = Pick Q = Quit:

These items are:

[a] The type of port in the the sector. Please put only Government
    Outposts in sectors numbered less than 20.
[b] The name of the port. Do not name ports that do not have ports, or
    that have Discoveries or Ion Storms. You might wish to change
    the name of sector 1 to EARTH.
[c] The objects in this sector. Each sector may have up to 10 objects,
    these may be either possessions or cargo.
[d] The player numbers of the ships that are in this sector. DO NOT
    CHANGE SHIPS BELONGING TO PLAYERS, OR THE SYSTEM PLAYER GUARD, or
    you may confuse the game.
[e] The number of the player that owns the sector. DO NOT CHANGE THIS.
    You can change this to a valid player number if you also make sure
    that there is a GUARD in Ships Here. DO NOT do this for sectors
    that have ports, sectors containing ports cannot be owned (under
    normal circumstances, see the SpacePlayer.txt file).
[f] The sectors that this sector connects to. 0 is no connector, the
    rest must contain valid sector numbers.

The options below the sector record are:

S, N, L, P, Q  These act the same as they do on the edit player menu.
s This allows you to search the entire galaxy for a particular ship
  number.
o This allows you to search the entire galaxy for sectors owned by a
  particular player number (similar to [F] Find Owned in SpaceDoor).
  The time this takes depends on the size of the galaxy, but it isn't
  too bad with only 1000 sectors.

THAT'S ALL FOLKS
~~~~~~~~~~~~~~~~
  That is about it for SpaceEd. I will be happy to answer questions for
registered users. A few final notes:

 - DO NOT use SpaceEd while someone is playing the game.
 - SpaceDoor has not been tested with more than one player playing
   at the same time. It should work ok, as long as both players don't want
   to access the data files at the same time. Files are opened as needed,
   then closed right away. You may wish to try setting SpaceDoor up to
   run in a DLG batch file, it shouldn't be too hard to check to see if
   the game is already in use from this type of file.
 - The long sector report generated under Extras is just that, long. A
   1000 sector data file might make a report well over 100K. The player
   report generates several lines of data for each player.
 - The Lattice stack checking code seems to be confused by DLG, so
   it has been disabled in SpaceDoor (-v option on LC). I don't really
   know what size stack SpaceDoor needs, everything in my DLG system
   gets a 25K stack, but it shouldn't need anywhere near this much.
   Still, better safe than sorry...
 - SpaceDoor traps any ^C characters it gets from DLG. When it gets
   a ^C, the current player and sector data are saved, and the game
   then exits. This will help prevent users from hanging up during
   the game in hopes of getting their old data back when they do
   poorly in the game.
 - If you wish to run SpaceDoor locally, you must run it in a raw:
   window. You would need two batch files to do this, spaceshell
   and spacestart. Place them both in your Space: directory.

    Spaceshell:
      Space:SpaceDoor "Your Name"
      endcli

    spacestart:
      newshell "raw:0/0/640/200/SpaceDoor" from Space:spaceshell

   Then, to play locally, type (at the CLI):
      execute space:spacestart
   You could type the spacestart file at the CLI instead every time,
   or set an alias in your regular shell-startup file.

  This is the first version of SpaceDoor. I don't know if there will ever
be a new version. I plan to write a few utilities to run at set times
under TPTCron, wether I do so depends upon what type of response the game
gets. Possible utilities include:

 - A program to generate a player scores text file.
 - A program to delete players who haven't played within a set
   number of days.
 - A program to apply a specific change to each player (for example,
   change everyone's cash to 1000, or give everyone 99 turns, etc).
 - Anything else that might be useful. If you have any ideas, let me
   know.

  SpaceDoor was written using Lattice C 5.04, on an Amiga 2000 with
3 megs of RAM, a 2091 HD controller, and a Quantum 40 meg hard drive.
