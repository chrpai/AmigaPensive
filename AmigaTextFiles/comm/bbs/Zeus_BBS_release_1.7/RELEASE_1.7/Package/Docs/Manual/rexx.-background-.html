The ARexx Command Set

Introduction

Zeus has over 300 ARexx commands. This manual attempts to document all these commands, with examples, along with how to use Zeus from both a SysOp's and user's point of view, with tutorials.

How to read this documentation:

Each command is outlined using several fields. (For the interested; this is what is known as the Amiga AutoDoc format, and is in a similar format as that used to document the Operating System's programmer interface). 

   NAME

       The actual command name.  This is the ARexx command you use,
       followed by a short description.  For example:

       GetPointer -- Returns pointer data about an area number.

   SYNOPSIS

       The syntax with psuedo arguments on how the function works.
       Options enclosed in <> brackets are required to be passed to
       that function. Options enclosed in [] brackets are optional.
       Options in upper case and not enclosed in brackets are
       keywords. These keywords must appear for the option to be
       used. Any options separated by a vertical bar are mutually
       exclusive, meaning that the argument to the function takes
       one or the other.  For example:

       GetPointer [Area Number] [LOW|HIGH|HSBN]

   FUNCTION

       A detailed description of what the function does, why it
       does it, what it's for, and anything else to look out for.

   INPUTS

       A detailed description of each option outlined in the
       SYNOPSIS.

   RESULT

       The RESULT variable returned in ARexx from the function.
       This variable may be alpha-numerical.

       For more information on why commands might return data
       in a variable named RESULT, see the chapter on ARexx
       programming.

   RC

       The RC variable (Return Code) returned in ARexx. This value
       will be numerical. This is normally, but not always, used
       to indicate an error. Many commands return a standard
       value here,

       0     -     Command executed OK

       5     -     Warning - command did not fail, but some
                   special circumstances occured.

       10    -     Bad arguments

       20    -     Fatal error - usually indicates out of memory

       Differences from this are always noted in this section,
       so don't take the values for granted.

   EXAMPLE

       If applicable, this section contains an example on using the
       function. Often there might be a pointer to a script
       provided with Zeus which provides a good example.

   NOTES

       Things you should know about the function to resolve any
       problems and avoid conflicts.

       This also indicates command availability:

       Asynchronous

       This command is asynchronous and can be used in a .Rexx
       script externally from the Zeus ScriptSet (while Zeus is
       running). Many scripts in the Zeus:Rexx/ directory will use
       these commands.

       Line

       This command can be used externally in a Rexx script but
       requires a line argument.ie. Parse Arg Line or Line = 0

       Zeus

       If no mention is made, or it does mention "Zeus", this
       command can be used in a .zeus script (the scripts used to
       `drive' the BBS). All commands will run in a Zeus script,
       which is why we don't often mention it here if there is not
       a special reason to.

   SEE ALSO

       References to other commands that are associated with this
       one and might be worth looking at.
