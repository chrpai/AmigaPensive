Chapter 13 - DataManager

The DataManager is a program called by the MsgConfig and FileConfig preferences programs. It was used in Zeus 1.0, was excluded from Zeus 1.1 but is back from Zeus 1.2.

It is designed to alter the data files on disk to match changes made to the configuration of message and file areas. Currently, it can only handle the Zeus native libraries (those named fbzeus and mbzeus). As an example, what if you had the following message areas and wanted to move WORKBENCH to a more favourable position (using the "Number" button the MsgControl->Areas window)?

From:

10 - Amiga
11 - Amiga
12 - Workbench

To:

10 - Amiga
11 - Workbench
12 - Amiga

Firstly, if you post messages using Zeus:Bin/PostMsg into either Workbench or Amiga using either's area number, the messages will now go into the wrong area. If you often renumber areas, it can be annoying to change your off-line message posting scripts continually. Get around this by using "PostMsg TAG=<tag name>" instead of the area number, where <tag name> is the external tag of the area, such as WORKBENCH for FidoNet or alt.amiga.workbench for UseNet.

Now you have the problem that after renumbering the areas like this you have messages for Amiga in your Workbench area and vice versa! This is where the configuration program's "Update data files" checkmark comes in (on the "Save.." window). If it is left checked when saving, it will call the DataManager.

However, before using DataManager you must ensure you renumber the areas carefully:



In the above example picture, 11 is renumbered directly to 12 and 12 renumbered directly to 11. This is bad. DataManager will first renumber 11 to 12, and in doing so it will erase area 12's original data files - which still contain our Workbench messages! Then, 12 is renumbered to 11 which mean our Amiga messages will end up back where they started but Workbench's will be deleted.

Instead, follow this slightly more round-about method of renumbering while in the MsgControl program:

Renumber 11 to 13 (or another unused area number)
Save and run DataManager (click "Go All").
Renumber 12 to 11
Renumber 13 to 12
Save and run DataManager (click "Go All" again).

Now no data files will clash at any time.


Running DataManager Separately

If you did not opt to update the data files when saving the configuration, you can still update afterward using DataManager itself. 

Zeus:Utils/DataManager ?
PUBSCREEN,FE=FILEEVENTS/S,ME=MSGEVENTS/S,USAGE/S:

PUBSCREEN       -- Set the screen DataManager appears on. E.g, Zeus.
FE=FILEEVENTS/S -- Process file area change events.
ME=MSGEVENTS/S  -- Process message area change events.


This can be useful if you are writing a program to handle Zeus's configuration, and want to take advantage of DataManager to update areas afterwards. The ZMF.library contains functions used to facilitate using this, so programmers can check the documentation for that.
