Chapter 15 - Multiple Paths for each File Area


How MultiPaths Work

File areas in Zeus are given one main path per area, defined in the main area edit window in Prefs/FileConfig: 

FileBase
   |
   |- Area
   |   |- Name
   |   |- Path
   |- Area
       |- Name
       |- Path


MultiPaths allow you to give every area as many Path elements as you want: 

FileBase
   |
   |- Area
   |   |- Name
   |   |- Path
   |   |- MultiPaths
   |        |- Path
   |        |- Path
   |        |- Path
   |        |- Path
   |- Area
       |- Name
       |- Path
       |- MultiPaths
            |- Path
            |- Path



Reading Files

When Zeus looks for a file (e.g., when a user requests it for download, or FileManager wants to update its offline state), it first checks the "main path", and if the file is not found there each MultiPath is checked for the file in turn. Only the first file found is returned to the BBS, so you may have CD-ROM's with duplicate files (like AmiNet CD's, with the newest CD first) and the newest version is returned.



The Elements of a MultiPath

Each area may have as many MultiPath entries as you wish.

 · Path
The path from which to read and save files from/to.

· R/W (Read/Write) or Read Only
Defines how Zeus sees the path. All CD-ROMs should be set to Read Only, as well as any paths you don't wish Zeus to write to. This is discussed further below.



Use of MultiPaths

Here several scenarios are presented in which you may find MultiPaths of use:

Scenario 1:

You have AmiNet CDs online and wish to also download AmiNet from an FTP site to the same areas as those the CD take.
You configure the AmiNet mirror style file areas, and for each area point the main path to a directory on your hard disk and then one Read Only MultiPath for each CD.
You can now access all files from the BBS and also upload files to those same areas as if they were hard disk only. 

Area
 |- Path = HardDisk/Area/     <ReadWrite>
 |- MultiPaths
      |- CD1/Area/            <ReadOnly>
      |- CD2/Area/            <ReadOnly>
      |- CD3/Area/            <ReadOnly>



Scenario 2:

You have several hard disks, and wish to run your file base over them all. While with other BBS software you may have to define separate areas to each drive, we instead will create the same directory structure on each drive and in Zeus set one drive as the main path, then add the rest as read/write MultiPaths.
As each drive fills up, Zeus will automatically see this and begin saving new files to the next path which has enough disk space to spare, either the next new drive, or if the file is small enough to fit on a disk previously filled with a larger file, it will go there. 

Area
 |- Path = HardDisk1/Area/    <ReadWrite>
 |- MultiPaths
      |- CD1/Area/            <ReadOnly>
      |- HardDisk2/Area/      <ReadWrite>
      |- CD2/Area/            <ReadOnly>



Scenario 3:

You are running out of hard disk space, but are able to burn a CD-ROM of your file base and keep the CD available most of the time.
This is done in a way identical to scenario 1, but you may wish to run "FileManager OFFLINE ALL" when the CD is removed and reinserted, to make sure Zeus knows which files are currently available.
