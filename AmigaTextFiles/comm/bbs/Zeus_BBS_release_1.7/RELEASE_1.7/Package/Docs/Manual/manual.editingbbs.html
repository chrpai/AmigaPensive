Chapter 14 - Editing your BBS

The Greek God Zeus could come down to Earth in any form he chose. This myth
inspired the name of our BBS package. With a little work, your BBS can take any
form you wish to give it.

Introduction

This is possible through our ARexx host system. Every "script" may represent a menu, a sequence of events or a function script. A menu is a point within the BBS which takes input from the user (by means of the keyboard, mouse or appropriate input device) and acts upon it. A sequence of events is as it sounds, a list of "events" which the user is forced down (like a corridor), with input events separating each event. An example of a sequence of events would be the login sequence which is called immediately after a recognised user logs into the BBS. A function script is a script such as the "file listers", the "download option" and the "message read option".

The supplied script set

Supplied with Zeus is a "script set" - this controls the entire structure of the BBS that the user sees when they logon. Currently the "script set" provided is Wedlock BBS. However there are other "script sets" available with different structures which can be found on Zeus support sites. Space dictates that we can only document the default script set, and we recommend you get to grips with this first before attempting to use a different one or writing your own from scratch. All scripts adhere to a similar style, but are not interchangable, i.e. in most cases a script from one script set cannot be inserted into another script set!

The Text System

Introduction

Zeus offers a lot of flexibility when setting up text files for use in your BBS. The aim of the Text System is to send the text file which uses as many terminal options as the user supports, but does not send anything the user cannot understand.

There is a naming convention for text files which allows Zeus to pick the best match for the user online but with a fall-back option if that file does not exist.

IBM/Amiga ANSI codes supported
8 bit character translation
RIPscrip graphics protocol supported
Up to 256 Languages
Up to 256 Menu Sets
Menu Sets and Languages are totally independent
Up to 256 Access levels
Over 16 million possible filenames for each single text file!
User has complete control over what is displayed on their screen


Basic text files

If a file ends in .TXT it is assumed to be an ANSI/Plain text file. If Zeus is displaying it to a user with RIP enabled, it will send the codes to set an ANSI palette and reset the text window to full size before displaying the file.

The user may choose to disable ANSI codes in which case all ANSI codes will be filtered out (or expanded if possible) to produce a plain text file.

The user may also choose to disable 8-Bit characters which causes Zeus to use it's internal conversion table to find the best 7-Bit matching character.

Zeus will write a screens worth of text and then stop and ask 'More? Y/N/C' (or the string specified in Languages) but this can also be disabled if the user so wishes.

If the users terminal automatically expands a CR (Carrage-Return) to a CR-LF (Carrage-Return/Line Feed) pair, the user can ask for all line feeds to be filtered out.

Filename searching is performed like this:

Example Base name is: 'MainMenu'

Search #1: 'MainMenu' (Zeus always tries the base name first)
Search #2: 'MainMenu.!0' (Access level of the user online)
Search #3: 'MainMenu.TXT' (The default)

Note: If Zeus matches the base name then it always assumes it is an ANSI/Plain text file.


RIP files

If a file ends in .RIP it is assumed to contain RIPscrip protocol commands. It is sent to the user as normal but Zeus will not prompt for 'More?' if the number of lines in the file is greater than the users screen height. Apart from this they are treated exactly like .TXT files, except of course that the user's terminal program will interpret them as graphical menus.

Zeus will only look for .RIP files if the user has set the RIP flag, or there is no user online yet and Zeus has detected a RIPscrip terminal (See ARexx command: DETECTRIP)

Filename searching is performed like this:

Example Base name is: 'MainMenu'

Search #1: 'MainMenu' (Zeus always tries the base name first)
Search #2: 'MainMenu.!0' (Access level of the user online)
Search #3: 'MainMenu.RIP' If the user has RIP enabled)
Search #4: 'MainMenu.TXT' (The default)


Menu Sets

The default filename extension for menu sets is <Filename>.<MSNumber>

Zeus' Menu Sets are completely independant of Languages. A Menu Set is supposed to be a certain text style, format, or protocol. For example, you could set up five menu sets as:

0 - Plain Text (No flags selected)
1 - IBM ANSI (8 Bit Graphics, ANSI Codes)
2 - Amiga ANSI (8 Bit Graphics, ANSI Codes, Amiga ANSI)
3 - RIPscrip Graphics (8 Bit Graphics, ANSI Codes, RIP graphics)
4 - Animated ANSI graphics (8 Bit Graphics, ANSI Codes, No More prompts)

NB: The flags settings are defined in the Prefs/System program.

By defining menu sets like this you let Zeus know that when it opens a file called 'MainMenu.3' it contains 8 Bit characters, ANSI codes and RIP graphics which will affect how the file is displayed to the user.

If you have no menu sets defined, Zeus will not look for them when searching for a file to send to the user. If you have defined 1+ then Zeus looks for files in this order:

Example Base name is: 'MainMenu' and user has selected Menu Set #3

Search #1: 'MainMenu' (Zeus always tries the base name first)
Search #2: 'MainMenu.3!0' (Menu Set and Access level)
Search #3: 'MainMenu.3' (Tries the menu set extension)
Search #4: `MainMenu.!0 (Tries the access level)
Search #5: 'MainMenu.RIP' (Only if the user wants RIP)
Search #6: 'MainMenu.TXT' (The default)


Languages

Zeus allows you to run a multi-lingual BBS by defining languages. They are
totally independant of menu sets and the filenaming convention is:
<Filename>.-<LanguageNumber>. If you use this format then Zeus doesn't know what
is in the file and so it assumes it is ANSI/Plain text.If you want to define RIP
language files, see the section below on combining Menu Sets and Languages.

Example Base name is: 'MainMenu' and user has selected language #2

Search #1: 'MainMenu' (Zeus always tries the base name first)
Search #2: 'MainMenu.-2!0' (Language and Access level)
Search #3: 'MainMenu.-2' (Tries the language extension)
Search #4: 'MainMenu.RIP' (Only if the user wants RIP)
Search #4: 'MainMenu.!0' (Tries the access level)
Search #5: 'MainMenu.TXT' (The default)


Menu Sets and Languages

If you have defined Menu Sets and Languages, Zeus looks for files with the format <FileName>.<MenuSet>-<Language> as well as all the other combinations.

Example Base name is: 'MainMenu' and user has selected Menu Set #1 and Language #3

Search # 1: 'MainMenu' (Zeus always tries the base name first)
Search # 2: 'MainMenu.1-3!0' (MenuSet, Language and Access level)
Search # 3: 'MainMenu.1-3' (MenuSet and Language)
Search # 4: 'MainMenu.-3!0' (Language and Access Level)
Search # 5: 'MainMenu.-3' (Language)
Search # 6: 'MainMenu.3!0' (Menu Set and Access Level)
Search # 7: 'MainMenu.3' (Menu Set)
Search # 8: 'MainMenu.!0' (Access level)
Search # 9: 'MainMenu.RIP' (Only if the user wants RIP)
Search #10: 'MainMenu.TXT' (The default)

It is advised to enable text file buffering if you use menusets and languages!


Script name conventions

Scripts also use the text file naming convention, except when the RIP protocol is enabled the extension is `zrip', and the default script name is `zeus', e.g:

Example Base name is: 'MainMenu' and user has selected Menu Set #1 and Language #3

Search # 1: 'MainMenu' (Zeus always tries the base name first)
Search # 2: 'MainMenu.1-3!0' (MenuSet, Language and Access level)
Search # 3: 'MainMenu.1-3' (MenuSet and Language)
Search # 4: 'MainMenu.-3!0' (Language and Access Level)
Search # 5: 'MainMenu.-3' (Language)
Search # 6: 'MainMenu.3!0' (Menu Set and Access Level)
Search # 7: 'MainMenu.3' (Menu Set)
Search # 8: 'MainMenu.!0' (Access level)
Search # 9: 'MainMenu.zrip' (Only if the user wants RIP)
Search #10: 'MainMenu.zeus' (The default)

Structure of Menu Files

This chapter is concerned with editing menu files rather than function files. The structure of function files is very variable, and describing them all is out of the scope of this manual. Once you are confident with editing menu files to provide the options you wish to give your users, you should refer to the chapter ARexx Command Set and the AmigaGuide file Zeus:Docs/Manual/Rexx.guide. They contain descriptions of all the ARexx commands in Zeus, as well as example source of how they are used.

This is the source of a menu file.

Each menu file must contain the following segments:

Header Comment. All scripts must have a comment to start with. 

/*
** MainMenu.zeus -- The main menu.
**/


Header lines. All scripts must have these lines in order to set the variable `Line' which must be set to use the Zeus ARexx commands. 

Options Results

Parse Arg Line


Check that the user hasn't logged off while transferring scripts. ChkCarrier will return not equal to 0 if they have. 

ChkCarrier

IF RC ~= 0 THEN Exit


The main "loop": user's will be stuck in this loop until they select an option which transfers them to another script. When a command has finished executing within this script it will "Signal Menuloop" to jump back to this point. 

MenuLoop:

   Signal On Syntax


SetStatus sets the "Action" of the user, the line viewed from within the Voyeur program for the SysOp to keep tabs on the user and displayed to other users via "Who is online" doors. 

   SetStatus '"At Main Menu"'


Clear the screen and display the menu file `Main/MainMenu'. 

   ClrScr

   Display 'Main/MainMenu' IsMenu


Show any "events" such as node messages or 'new mail waiting' messages that have occured since the last check. 

   ShowEvents


Loop waiting for a key, and signalling the correct `CMD_' option if the input is a valid option. 

   DO FOREVER
      Prompt `MainMenu'
      Read IsMenu
      IF RC ~= 0 THEN Exit

      CmdString = RESULT
      Cmd = 'Signal CMD_'CmdString

      Interpret Cmd
   END


This tag is called if the user pressed the `?' key to request a redraw of the screen. 

/*
** Redisplay menu
**/

CMD_?:
   GetUserFlag 'Expert'

   IF RC = 1 THEN Display 'Main/MainMenu'

   Signal MenuLoop


This tag is called if the user pressed the `L' key to request to logoff the BBS. The user is asked whether they are sure they wish to logoff, if they are the `Logoff/Logoff' text file is displayed to the user and the current script is "cleared". Clearing the script means that the `Exit' script will exit out of the BBS, rather than returning to the previous script. 

/*
** Logoff
**/

CMD_L:
   CallScript 'File/QueryMark'

   Write '"[0;37mnAre you sure you want to logoff? "'

   GetYesNo 'Yes'
   IF RC = 10 THEN Exit

   IF RESULT = 'Y' THEN DO
      ClrScr
      Display 'Logoff/Logout'
      ClearScript
      Exit
   END

   Signal MenuLoop


This tag is called if the user pressed the `C' key to request to leave a comment for the SysOp. The current "SysOp Name" settings from the Prefs/System program is retrieved via. ControlCode 115 and pushed onto the input stack. 

/*
** Leave a comment to sysop...
**/

CMD_C:
   SetStatus '"Leaving feedback to Sysop"'
   RIPReset
   ChangeMsgArea ALL 1

   Write '"n[0;36mLeaving feedback to Sysop...n"'

   FlushInput

   ExpandCC '"%115|"'
   PushInput '"'RESULT'nr"'

   CallScript 'Messages/WriteMsg'

   Signal MenuLoop


This option calls the function script `Main/PageSysOp' to call the SysOp for a chat. 

/*
** Page Sysop...
**/

CMD_P:
   SetStatus '"Paging SysOp ..."'
   SetVar ZP||Line '" "' GLOBAL
   CallScript 'Main/PageSysop'
   Signal MenuLoop


This option passes control to the `Zeus/ZeusMenu' script. 

/*
** Zeus support menu...
**/

CMD_Z:
   NextScript 'Zeus/ZeusMenu'
   Exit


Through the use of the `Signal on Syntax' line used earlier we ensure that if none of the options above where selected then we match the keypress against the global command configuration and execute the ARexx segment that is returned. If the keypress does not match a global command then a `Signal Menuloop' occurs and transfers control back to the beginning of the script. 

/*
** None found, check for global commands.
**/

Syntax:
   GetGlobalCmd '"'CmdString'"'
   IF RC = 0 THEN Interpret RESULT
   Signal MenuLoop


Adding a link to download your file list:

To make an option to download a particular file directly from the hard drive, we'd add an option such as this: 

CMD_F: /* download file list */
   MarkDosFile `"Files:Filelist.lha"'
   if RC = 0 then
       CallScript `Files/Download'
   else begin
        Write `"File list not present!"'
        WaitReturn
   end
   Signal Menuloop


Removing the Zeus menu from the main menu:

If we wish to remove the option to visit the Zeus menu from the main menu we would simply remove the lines from CMD_Z: to Exit from the main menu script.


Global Commands

Global Commands are menu options available "system-wide", i.e. they can be accessed from any menu regardless of the code placed in the menu. Global Commands are configured in the file Zeus:Config/Zeus/GlobalCmds.cfg and take a similar format to the Editors configuration described in the "Message Subsystem" chapter. Pieces of Arexx are separated by a `#' character followed by the menu key option: 

#0
NextScript 'Main/MainMenu'
Exit

#1
NextScript 'Files/FilesMenu'
Exit

#2
NextScript 'Messages/MessagesMenu'
Exit

#3
NextScript 'Doors/DoorsMenu'
Exit

#4
NextScript 'Statistics/StatisticsMenu'
Exit

#5
NextScript 'Options/EditTerminal'
Exit

#6
CallScript 'Bulletins/BulletinsMenu'
Signal MenuLoop

#Z
CallScript 'File/QueryMark'
Write '"n[0;37mAre you sure you wish to logoff? "'

GetYesNo Yes
If RESULT = 'Y' Then Do
