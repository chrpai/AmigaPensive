  FREE FILE, What the hell is it ????

  Well, On some BBS Host software its possible to assign a FREE file area
  Allowing users to download files contained without affecting their ratio
  etc. FreeFile gives a sort of half way solution to this on a TransAmiga
  BBS.

  How Do I set it up ??

  Firstly there are 3 files, 'FreeFileV1.trans', The script, 'FreeFile.cfg'
  the config file, and 'FreeFile.txt' this text.

  Drop the file 'FreeFile.trans' into the directory with all your other bbs's
  scripts, normally assigned to BBS:Rexx/

  Edit the menu of your choice, I have it on my main menu and Filemenu,
  these filenames are BBS:Configs/Main.rx or BBS:Configs/File.rx

  Just follow the format of these files to add in the new line.

  Drop 'FreeFile.cfg' in to the configs directory, normally BBS:Configs/

  and just drop the text file.

  Now edit the FreeFile.cfg (in the BBS/configs dir) and tell it about the
  files you'd like to make available to users. The format is -

1     - Number of files setup (in the config included its set to 3)
Name  - Name of file as you'd like it to appear on the menu (20 chars max)
Filename - This is the path and filename of the actual file
10    - Access you'd like on the file.

  In detail now, the first number is the number of files that are contained
  with the config file, this tell the script how many it should be looking
  for.

  2nd, The name, this is so you can keep it simple for the user, if like me
  you put the OLR (off line reader program in there), you wouldn't want
  Q-BLUE07.lha appearing on the menu it would look horrible, just Q-Blue OLR
  is much nicer.

  3rd, Filename, including path,this is simple, its just where the
  script can find the file so it can send it to the user

  4th, Access, I make the FREE Files program available to first time callers
  who have an access of 0, so its okay for them to have a filelist, but I
  wouldn't want them having the OLR, or Extended filelist (look in my
  config included) until they've registered and their access go's up.

  Another example is , I've put an archive of my logs in there now aswell,
  since the CoSysOp's have a look through for strange things, this means
  they can get them now with ease, they have higher access.

  You just add files and make sure that the first figure reflects the number
  of sets of details below it.

  The next thing to alter is the script its self, the script thinks
  you have the same number of protocols as me, which is eight, if you do
  then you needn't bother to change it, but if you don't the line is half
  way down the first page of the script. PLEAE DON'T ALTER ANYTHING ELSE.

  What happends if it don't work ??

  Well, when you run it and you might find you get nothing on the menu
  presented, check that you've entered the correct path and filename
  to the files in the config.

  As the script loads the config, it checks to see if the file actually
  exists, if it doesn't it doesn't bother to display it on the menu.

  This might save the odd user saying 'Ooo, tried that free files thing,
  and it don't work'
