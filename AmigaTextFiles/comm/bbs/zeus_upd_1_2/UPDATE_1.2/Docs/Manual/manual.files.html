Chapter 6 - File Subsystem

File Areas are configured using the "Prefs/FileConfig" program. Upon loading the main window will appear:




Four aspects of the file configuration can be controlled using this program:


6.1.0 General File Configuration

Selecting the "General" option will bring up a new window:




Various options of the file subsystem can be configured with this window:


Memory Usage

Each line on the BBS uses indexing to speed up the file list searching. You can configure the size of these indexes. The size of indexes you use should be related to the amount of memory you have installed on your Amiga. 


Setting  Memory         Indexes   Usage
~~~~~~~  ~~~~~~         ~~~~~~~   ~~~~~
LOW      1 mb.or less   32        3k per index.

MEDIUM   1-2 mb.        128       13k per index.

HIGH     >2 mb.         256       26k per index.

OTHER    You may specify your own index usage settings in the string
gadget when using the "OTHER" setting.



File Notes

When a file is uploaded to the BBS, the file description given to the file is added to the AmigaDOS comment field. Due to restrictions in AmigaDOS, only the first 80 characters of the file description will be added. This option should be turned off when adding files from the CD-ROM to Zeus, as file notes may not be added to read-only devices.


Maximum Marks

The maximum number of files a user may mark on the Bulletin Board. Every file marked takes up disk space, and a user marking '#?' on the BBS could fill up your hard drive very quickly if you have a few thousand files. Plus the time that might be required to mark all files could be considerable..


Temporary Path

The path to copy files ready to be downloaded to. This path will only be used if "Copy Files to Temp" is set on in the file area definition.


Upload Path

The base path to upload files to. A directory will be created within this path called Upload<x>/, where <x> is the line number uploading, e.g. specifying dh2:Uploads/ as your upload path will cause files uploaded on line 1 to be sent to dh2:Uploads/Upload1/ for processing. This directory shouldn't be present in the Zeus file area configuration.


Save

Outputs the general file configuration to disk. The name of the general file configuration is "Zeus:Config/File/General.Dat" and is in binary format.


Quit

Leaves the general file configuration window. If you have not saved the configuration you will be prompted to.



6.2.0 File Area List

File areas can be configured in the "Areas" window of the Prefs/FileConfig program..



This main window controls your file area list.

Add - Add a new file area to the list. The file area list is sorted numerically and a new area will be inserted according to its number.

Edit - Edit the file areas(s) currently marked. Single areas can be marked by double-clicking on the area you wish to edit.

Copy - This will make duplicate copies of the currently marked file area(s).

Delete - Remove the currently marked file area(s) from the file area list.

Number - Renumber the currently marked file area(s). A requester will pop up allowing you to decide the base number to renumber from.

Save - Outputs the file area list to disk.

Quit - Leaves the area list window. If you have changed the file area configuration, a window will pop up.



6.2.1 The File Area Definition

File Area Definition Picture


Selecting 'Add' or 'Edit' will bring up this window, allowing you to edit the attributes of each file area. Editing of the file area definitions can also be done through the Zeus ARexx port. See the commands SetFileArea and GetFileArea in the reference section of this manual.

Each field may also be accessed through control codes while a user is online. See ControlCodes %1000 and onwards in the reference section of this manual.

Settings


Number - The index number of this file area. No two file areas in the file area list may have the same number, and if you attempt to enter a duplicate number a requester will popup and make you rechoose. Please note Zeus does not support the use of an area 0 anywhere on the BBS.

Name - A descriptive name for this file area. Up to 64 characters may be used, though for two column file area lists on the BBS to be formatted correctly, a maximum of 30 is recommended.

Path - The main path for storing files belonging to this area in. This may be any valid AmigaDOS path of up to 104 characters long. A '/' or ':' character will be appended to this path if you do not supply one. E.g., entering dh2:aminet would be replaced with dh2:aminet/

Library - Set a File Base library for this area. This allows programmers to write libraries which allow Zeus file bases to be stored in any format - for example, an FTP library would allow files to be stored on a remote FTP site, but look to be present on your BBS. File base libraries are libraries pre-fixed with "fb" - the default library being fbzeus.library. Select a new library using the file selector icon to the right - but only select fb#?.library's ! An incorrect one may crash File Config. If the library has a configuration window, "Opts" will show this.

Write access - This cycle gadget allows the SysOp to allow or disallow write access to this path. CD-Rom drives for instance may not have R/W access as they are a read-only medium. This cycle gadget may have either a "R/W" or a "Read" setting.

Disk icon - This icon will bring up a file requester allowing you to select the main path for this area easily.

Low - The "override" minimum access level required to access this area. Template and SIG definitions take second priority to this setting. See section 8 for more informatioin on restricting access to users on the BBS.

High - The "override" maximum access level required to access this area. A setting of 255 is common in almost every case.

Age - The minimum age a user must be to enter this area. This setting is useful for restricting access to "over-18" file areaa.

Gender - This cycle gadget allows you to prevent access to this file area for Male or Female members of the Bulletin Board.

U/L BPS - This setting defines the minimum modem speed required to upload a file to this area. Typical settings are "1200" or "2400" to disallow the slower modem rates.

D/L BPS - This setting defines the minimum modem speed required to download a file from this area. Some SysOps will only allow high-speed (over 9600 bps) users to download from their file bases.


Multiple Paths - If the files in this file area are stored over more than one path, for instance if you have more than one AmiNet CD and you wish to incorporate each directory on the CD into one directory on your BBS you should use the Multiple Paths option. Clicking this button will bring up a new window.



An unlimited number of paths may be stored in this window.

New: - Adds a new entry to the list. This entry may be changed with the Disk Icon (will bring up a file requester to allow you to select the path), or the string gadget in which you can enter the path directly.

Del: - Deletes the currently selected item from the list.



Flags


Allow Downloads - Allow users to download files from this area. Typically set on.

Allow Uploads - Allow users to upload files to this area.

View Files - Allow users to view the files in this area.

Make Files Free - All files in this area will default to "free access". This means that the user's download ratio will be unaffected when accessing files in this area.

DOS FileNames - This setting truncates uploaded files to the MS-DOS 8.3 character file format. Zeus file bases usually allow file names of up to 30 characters which may be unacceptable to some MS-DOS machines. For instance, if this flag is set ON, the file "obnoxiouslylongfilename.zip" would be truncated to "obnoxiou.zip". Multi part files are also catered for with this algorithm, e.g. "obnoxious_part1.dms" and "obnoxious_part2.dms" would be truncated to "obnoxio1.dms" and "obnoxio2.dms".

Validation Required - The SysOp must "hand-validate" using the Utils/FileEditor program each new upload to this area before users can download them. See section 8 for more information on allowing users to access unvalidated files.

All Files to Temp - Files to be downloaded from this area will first be copied to the "Temporary Path" as specified in the "General File Configuration" window of Prefs/FileConfig. Use this when the storage the file is on will be too slow to send over the link the users might be using, or, if you have a multi-disk CD-ROM, this option will avoid any excessive switching between disks.



6.3.0 Transfer Protocols

The transfer protocols callers to the BBS may use to upload and download files may be configured by selecting "Xfers" from the main FileConfig window.



Add - Adds a transfer protocol to the list.

Double Click - Edits the transfer protocol you have selected.



Up - Moves the transfer protocol up one place in the list.

Down - Moves the transfer protocol down one place in the list.


Information about transfer protocols

Zeus comes supplied with two transfer protocols built-in. These are executable programs stored in "Zeus:Bin/System/" and are called "HydraXfer" (for Hydra bi-directional transfers) and "LocalXfer" (for simulating an upload from the local terminal). Other popular transfer protocols like "XModem", "YModem" and "ZModem" may be added using the "XPR" library system.

XPR libraries are standard Amiga libraries, commonly stored in LIBS:, which handle the uploading and downloading of files. There are many different XPR protocol libraries available, but Zeus comes with the following ready configured.

The libraries themselves can be found on Zeus Disk #3, in the XPR.lha archive. 

Protocol Name   Library                 Version Flags   DL Options      UL Options
XModem          xprymodem.library       2.20    -----   Z1 C1 B0 YS     Z1 C1 B0 YS
XModem-1K       xprymodem.library       2.20    -----   Z1 C1 B1 YS     Z1 C1 B1 YS
XModem-1K-G     xprymodem.library       2.20    -----   Z1 C1 B1 YG     Z1 C1 B1 YG
XModem-CRC      xprymodem.library       2.20    -----   Z1 C1 B0 YS     Z1 C1 B0 YS
YModem          xprymodem.library       2.20    BDU--   Z1 C1 B1 YB     Z1 C1 B1 YB
YModem-G        xprymodem.library       2.20    BDU--   Z1 C1 B1 YG     Z1 C1 B1 YG
ZModem          xprzmodem.library       2.0     BDU--   TN OR B16 F0 E10 AN DN SN RN    TN OR B16 F0 AN DN SN RN



Editing the file transfer protocol



Name - The name of the file transfer protocol as seen by the user.

Library - Library name of XPR protocol, or the executable file to be run if in "Executable" mode.

D/L Options - XPR options to be passed to the library for downloads. Refer to your XPR library documentation for more information about these settings.

U/L Options - XPR options to be passed to the library for downloads.

Low Access - The minimum access level required to access this protocol.

High Access - The maximum access level required to access this protocol.

Batch files - This protocol supports the sending or receiving of more than one file at once.

Auto download - Flag to indicate whether the protocol does initiates transfers automatically.

Auto upload - Flag to indicate that the protocol supports upload without prior entering of file name(s).

Executable - Setting this flag to on means that the Library field is a program to run, rather than the name of an XPR library.

Bi-Directional - Indicates whether the transfer supports uploading and downloading at the same time.



6.3.0 Adding files to the BBS

There are many ways to add files to your BBS. The easiest is using Zeus:Utils/FileEditor. It can also be accessed from the Files->File Editor entry in the Control menu.

The File Editor

Upon loading the File Editor the following window will be displayed:



The large listview on the right doubles up as an area list and a file list. When the File Editor is first loaded the list of areas will appear, clicking on one of these will bring up a list of all the files in the area.Clicking on the "..parent" entry will bring you back to the area list.

The project menu from the menubar allows you to access some important general features of the File Editor:

About
Displays a small about request.

Iconify
Iconifies the File Editor on the Control Screen.

Edit Menus
Fires up the Prefs/MenuEditor program to allow you to edit the menu bar of the File Editor (see Section The MenuEditor).

Reload Menus
Reloads the menu configuration after editing with the "Edit Menus" function.

Quit
Quits the File Editor.


The second bevel box on the left contains "search controls". They allow you to filter the files displayed in a certain way:

Chrono
This mutually exclusive button allows you to choose between the files being displayed chronologically (i.e. by date), or alphabetically.

Forward/Backward
This set of buttons allows you to read the list forwards or backwards, e.g. if this was set on backwards in alphabetical mode the files would be listed from Z-A.

All/Validated/Unvalidated
This cycle gadget allows you to view files according to whether they have been validated by the SysOp, not validated yet or not to filter at all (all mode).

Clicking on a file in the list will display it's "file catalogue data". For every file which is on the BBS the file catalogue stores information about it:



Number - A unique number identifying the file in the file base. No two files may have the same number, and the number may not be changed.

Name - The name of the file. Zeus does not allow file names to contain more than 31 characters, and the first character of the file may not be a character other than a letter or a number.

Downloads - The number of times this file has been downloaded on the BBS.

Size - The size of the file in bytes.

Uploaded By - The name of the user who uploaded this file.

Upload Date - The date this file was uploaded in the format "dd-mmm-yy hh mm ss"

Last Dl - The last date this file was downloaded in the format "dd-mmm-yy hh mm ss".

Offline - Is the physical file offline? This flag is not updated automatically, use the FileManager program in "OFFLINE" mode to set all the flags.

Free - Will this file debit the user's downloaded file counters?

Validated/ Unvalidated - Has the SysOp decided that this file is fit to be on the BBS?


If you wish to edit any of this data you must press the Update Filebutton after you have made the appropriate changes.

Once you have selected a file area the file menu becomes available. From this menu you can manipulate the file base in various different ways:

Add File - Allows you to add a file from your hard drive to the file base. This option firstly opens a file requester to let you select the file, the current directory will be the main path from the area definition. Then you may add a short description of upto 256 characters. To add a larger description later you should select the file and ue the Edit Description option from this menu.

Bulk Upload - Allows you to add more than one file at the same time using a multi-select file requester, and lets you retrieve the file description either from the AmigaDOS file comment or by entering a global description for all files.

Delete File - Deletes all the selected files in the current area. You will be prompted to decide whether you wish to delete the physical files as well as the file catalogue entries.

Move File - Allows you to move all the selected files from one area to another, retaining their description and data. After selecting this option you should choose the area to move them by selecting another area.

Edit Description - Loads your local editor up and lets you change the description of a file. To configure your local editor you can use the option Configure Editor from the Prefs menu within File Editor.

Bulk Validate - Validates all unvalidated files within the area.

Unlisted Files - Shows all the files within the search paths of this file area which have notbeen added to the file catalogue. When you are in unlisted files mode you can automatically bulk upload the entire list by selecting the Bulk Upload menu option.

Find File - Prompts you for a name and jumps directly to that file. AmigaDOS wildcards are not used, the name must be exact.

Select All - Marks every file in the current area.

Deselect All - Unmarks every file in the current area.

Next Suitable Area - Jumps to the next area with "suitable" files in. If you have selected a search mask such as Unvalidated files only then it will skip file areas with only validated files in.

Previous Suitable Area - Jumps to the previous area with "suitable" files in.


The "Scripts" menu is entirely configurable through the MenuEditor program. It comes with three menu items pre configured:

Rebuild Catalogues - A hotlink to the RebuildCatalogues shortcut (see Section Shortcuts)

Renumber Catalogues - A hotlink to the RenumberCatalogues shortcut.

Extract FILE_ID.DIZ - This script uses the FileEditor ARexx port to extract the FILE_ID.DIZ files from the archives marked and add it in as the new description. The script called is "Zeus:Rexx/FileEditor/ExtractDIZ.zeus" and uses the Archivers Configuration to extract the files fom the archive correctly.


Adding AmiNet CD's to the file catalogue

The Bin/ZAmiNet utility has been provided to allow you to upload files from your AmiNet CD's to the BBS. In order to upload files from the "FILES.BBS" or "INDEX" description files you must have already created the areas on your BBS. This can be acheived very easily using the Zeus:Rexx/FileAreas/AddCDAreas.rexx script.

Adding Areas

Create a list of all the areas you wish to upload from the AmiNet CD to a file,
each area separated by a new line and call it "Areas.txt", e.g.: 

1> type Areas.txt

comm/bbs
comm/dlg
comm/tcp
dev/c
dev/e
util/misc


Run the following command, where "CD0:Aminet/" is the first part of the path
used to locate files in this directory. For example, for "comm/bbs" we would
search fo the files in "CD0:Aminet/comm/bbs". "200" is the number you wish to
start numbering the areas from. In this example "comm/bbs" will be area 200,
"comm/dlg" area 201 etc. 

1> rx Zeus:Rexx/FileAreas/AddAreas Areas.txt CD0:AmiNet/ 200



Adding Files from the CD

To upload the files from these areas we would run Bin/ZAmiNet in the following mode: 

Zeus:Bin/ZAminet AREAS 200-205 INDEX


This specifies that we wish to upload areas 200-205 (this is a "range" argument), and we wish to retrieve the file descriptions from the "INDEX" file located in the path, CD0:Aminet/comm/bbs/INDEX for example.

If your AmiNet CD does not have the INDEX format but instead uses the FILES.BBS format then the following line could be used: 

Zeus:Bin/ZAminet AREAS 200-205 INDEX



Adding a large number of files.

The Bin/FileManager utility is provided to make uploading many files to the file catalogue easy. Running in "ADDNEW ALL" will cause it to scan all the file areas searching for files that are in the area's physical path(s) but not in the file catalogue. Once it has found one it will ask you if you wish to upload it to the file catalogue, and prompt for a description. If you wish to add the files using the description provided in the AmigaDOS file comment then add the argument "FILENOTE".

To upload all new files in a <AreaNumber>: 

Bin/FileManager ADDNEW AREAS <AreaNumber>


To upload all new files on the BBS using the FileNote description: 

Bin/FileManager ADDNEW ALL FILENOTE



Tidying up your file base

If you have file catalogue entries with no matching physical file due to a
partial file loss then you can delete all the file catalogue entries using the
FileManager with the "EXISTS" argument. This will search for the matching
physical file in the area's path(s) for each file catalogue entry it finds and
prompt you if a mismatch is found. You can opt to delete all files using the `a'
key when the first mismatch is found.

To delete all non-present file catalogue entries: 

Bin/FileManager EXISTS ALL


To delete all non-present file catalogue entries in a particular area 

Bin/FileManager EXISTS AREAS <Area>
