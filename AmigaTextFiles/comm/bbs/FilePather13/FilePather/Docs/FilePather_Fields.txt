    ========================================================================
     2.0.0  INTRODUCTION
    ========================================================================

     This  documents  main  intent is  to describe the standard for making a
    history file within a file or archive. The list may be  looked upon as a
    log file, containing information about the places the file has travelled
    through, on its journey to you.

    The  list  may  be  used  in  a  separate  file,  named  'FilePath.lst',
    or supplied inside of another file.  However, no matter how the  list is
    connected  to  different kinds of objects,  the standard  format  should
    ALWAYS be readable in ASCII-format. Exception for  this rule is when the
    list is added  (archived) in an  archive as a file,  in which the actual
    ASCII list remains intact.

	

     2.1.0  BACKGROUND
    -=================-

          One day I came to think of how  interesting it  would be to really
    get  some use  for the  BBS  ads  that I  found in my  downloaded files.
    Eventually I decided to make a program that would only place ONE line of
    text into a file, instead of  having a multiple of files hanging around.
    The  FilePather  idea  was  borned.   In  the  beginning,  all  sort  of
    information  was  placed in  fixed fields in the line, but eventually it
    was stripped  down to just  contain the fields that are there today. The
    following things have been held in thought when designing the standard:

    · The list should be readable as usual ASCII text.
    · It should be possible to add custom information in an easy manner.
    · The  information  in  the line should  be parsable, so the information
       could be extracted easily by an automatic process.
    · If other platforms would like to adopt the idea, it should be possible
       to exchange files between the platforms.

    On the last point, I think I failed. Some  systems (PC & Macintosh) uses
    both Carriage Returns AND Line Feeds to signal End Of Line. Although the
    text is readable on the Amiga, it looks so  goddamn ugly, that I choosed
    to  not  add  Carriage Returns  at  the  end  of the lines.  Still, it's
    possible  to parse lines  looking from the  technical side. But the list
    will  not  look  pretty if  there for  example are  some  extra Carriage
    Returns on some lines.

    The first release of the program  'FilePather', passed the world without
    any  major  notice.  This  was  probably  an  result  of my non-existing
    attempts to  commercials.  Actually, I  was more in for programming than
    spreading the word, and the poor result might have  something to do with
    this.


    ========================================================================
     3.0.0  THE LINE FORMAT
    ========================================================================

        This section decribes the different fields in the FilePather line,
    and how they should be used.


     3.1.0  TEMPLATE
    -===============-


        BBS	Wedlock		Halmstad,Sweden
        <Type><TAB><Name><TAB>[<TAB>][<TAB>][<Sysop>"/"]<Location>

        		19:54 30-07-94
        <TAB>[<TAB>][<TAB>]<HH:MM DD-MM-YY>

         +46-035-186514
        <SPACE>"+"<Country code>"-"<Areacode>"-"<1:st number>


        ["|"<2:nd number>][|N:th number]

         Modem=V.32bis Message="Bonk!"
        [<SPACE><Custom_1:st>][<SPACE><Custom_2:nd>][<SPACE><Custom_N:th>]


     3.2.0  DESCRIPTION OF THE FIELDS
    -================================-


    Explanation of the different fields, default field widths in
    parentheses.

    (xx=No max value)
    The current versions of FilePather and FPBase will not  truncate strings
    longer than  the max values  stated here, but a future version might do.

    'ELAJTED' TEXT IS STRONGLY  DISCOURAGED!  Texts like '/|<//|><' (AJAX :)
    is NOT legal! Also, only 7-bit ASCII is allowed to avoid confusion.

    TAB length should be set to 8.

    Entries  enclosed  with  square  brackets  "[]",  are  optional.  If one
    optional entry  is included in the line,  there is sometimes a second or
    third entry that should be included too.


    Name            Max Width   Description
    ------------------------------------------------------------------------
    <type>              7   (7) The type of the  person/program that started
                                FilePather.  ie. User, BBS, Trader,Board, or
                                Program (for a  fileprocessor  like DIZ-ED).
                                'Board' are  reserved  for  'elite' BBSes to
                                sort them  out from usual BBSes.  If Type is
                                set to 'Program'  then  Name is  the name of
                                that program, SysOp is the author, Number is
                                the number to the author (data).

    <TAB>               1       The character that  tells a program which is
                                parsing the line, that <type> has ended, and
                                <name> is coming up. 

    <name>              31 (23) The name of the  person/BBS/program etc that
                                started  the  fileprocessing.  ie.  Mitnick,
                                John Smith, Inside Out, Wedlock etc.

    <TAB>[<TAB>][<TAB>] 1-3     Since <name> can be of any  lenght between 1
                                and 31, the field is  filled with TABs until
                                the   default   width,   23  characters,  is
                                reached.  Note that although it doesn't look
                                good,  more  than  23  characters is allowed.

    [<sysop>]           31 (23) The  sysops  name if applicable. NOTE! It's
                                perhaps  not  possible to fit your name here
                                together  with the  location! Use the custom
                                field 'Sysop'  if so. NOTE!  This field is a
                                'subfield'  of  <location>.  Therefore can't
                                <sysop>  and  <location>  together exceed 31
                                characters.

    ["/"]               1       This character  divides the sysops name from
                                the location. Therefor,  neither  <sysop> or
                                <location>  is allowed  to  contain slashes.
                                Note  that  this  character must to be taken
                                into  account  when  calculating  the  field
                                length.

    <location>          31 (23) Either the geographic  location or the group
                                name. If  the  case of  geographic location,
                                a comma "," is  used  to  separate  the town
                                name from the country name.

    <TAB>[<TAB>][<TAB>] 1-3     Fills out the field if neccesary.  The first
                                TAB signals 'End Of Location'.

    <HH:MM DD-MM-YY>    14      The time and date when the line was created.

    <SPACE>             1       Divides the  time and  date  from the number
                                field.

    "+"                 1       Tells  that this  number is an PHONE number,
                                not an netadress etc.  In the future,  other
                                characters  can  be defined  to signal other
                                types of numers/addresses.

    <country code>      x       The country code for the phoneline.

    "-"                 1       Divides country code from areacode.

    <areacode>          x       The areacode  for the phoneline.  I'm  still
                                considering to let unneccesary digits (0) to
                                be  enclosed  with  parenthesis, eg '(0)35'.
                                Since they  doesn't make  any diffrence when
                                dialing, except that it takes a little  more
                                time  to  dial, they  can  just  as well  be
                                included. Since  some  people probably can't
                                hold  themselves  from  adding  parenthesis, 
                                should your code  be  able  to handle these.
				(I've heard they use '9' to  begin areacodes
                                with in Spain.)

    "-"                 1       Divides the areacode from the local numbers.

    <1:st number>       x       Local number.  If there are no number or you
                                doesn't  like  to   spread  it,  set  it  to
                                'UNPUBL'  (as  in  'UNPUBLished' or  perhaps
                                'UNPUBLic'). This way it's still possible to
                                see in  what area  you are located,  and  to
                                sort the entries after country and area. The
                                local  number   may   contain  "-":s.  Start
                                parsing from the left to  make sure that you
                                aren't reading these.

    ["|"]               1       Divides the local numbers from each other.

    [<2:nd number>]     x       Another  number,  with the same country code
                                and areacode.

    ["|"]               1       Divides the local numbers from each other.

    [|n:th number]      x       Yet another number.

    <TAB>               1       Signals   'End Of Numbers'.  NOTE!  Previous
                                versions  of  this  document stated  that it
                                should  be  a SPACE here. Accidentally a TAB
                                was used instead. Since a TAB is much better
                                (?) we go for that instead.

    <custom_1:st>       x       A  custom  field.  This  fields  are totally
                                optional. All customs fields looks like:
                                Keyword=String
                                or:
                                Keyword="This is a string" 
                                or:
                                Keyword
                                See   the   file  'Custom_fields'  for  more
                                information.

    <SPACE>             1       The  custom  fields  are separated from each
                                other by a space.

    <custom_2:nd>       x       Another custom field.

    <SPACE>             1       Separator.

    <custom_n:th>       x       Yet another custom field.

    [CR] LF [CR]        1-2     The  stopmark  for  the  line.  Is  always a
                                LineFeed,  but  can have either a preceeding
                                or  a trailing  Carriage Return  appended on 
                                it.

     4.1.1  JOINING `Users Standards Group'
     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
     You can join the group by simply sending an e-mail letter to any member
    of USG, or via snail mail.

     Development  teams  and  other  groups  may  become members under their
    groupname,  which  means that every single groupmember needn't join USG,
    just  the group.  Groups should substitute `name' below for `groupname',
    and  disregard the `age and occupation' entirely.  A presentation of the
    group  would  also  be nice, like what you do, on what platform you work
    and so on. Single members of the group could also be "separate" members.


     When joining, you are required to enclose the following information;

         Your name
         Your address               (withheld from the public on request)
         Your country
         Your e-mail address        (if you have it)
         Your age and occupation    (optional information)
         A brief presentation       (optional information)

         Information on any software you are developing


     That's  it!   No fees or demands whatsoever!  One simple letter and you
    are  in.  If you use email, you'll probably receive confirmation of your
    membership in USG.

     USG  began in Sweden, but soon branched out into Europe, sooner than we
    expected,  so  don't let your nationality stop you; Everyone is welcome!
    We hope that you do join,  if not for anything else, then join because
    you support this standard.
