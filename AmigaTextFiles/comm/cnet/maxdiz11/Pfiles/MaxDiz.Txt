/X\axDiz (V1.10) Release Time Update Info
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~   

Changes (05th-July-94) - 100% completed & ready for release!! :)

1) Added A New Command (Sysop Only) From Main menu.  Enter `DIZCONFIG!'
   And You are then entered into A BBS ADVERTISMENT LISTING.  You Can
   Enter know BBS ADD's Filenames with WildCarding if need be.  Anything
   Enetered here will be removed from any uploaded File Archives..

2) Last Little bug Removed.. TYPING `SENT' Or `DIZCONFIG' From The Main
   menu with extranious characters.. ie `SENT f' Would send /XaxDiz Into
   Wrong Routines and start editing the last Listed Description..  Wierd,
   But solved.

3) I noticed that when entering R<FileNumber> in the udbase, the description
   was printed twice.  Don't understand this myself, but I deleted the 
   _TEXT file in the areas DATA directory and replaced it with a Zero
   byte replacement file and this solved the problems.  Future responces to
   files where saved okey and no further double displaying accured. I think
   this is just caused by having numerous File_ID processors installed in 
   the past.

4) MaxDiz Now uses an assign to access the Long Descriptions Directory.
   If you Entered `CNET:DESRIPTIONS' in the config for example, and 
   a user Global Searched for `CNET' then every accurrence of a LONG
   Description within the UDABASE was displayed..  The Assign is done
   by maxdiz, and doesn't interfere with previous MaxDiz Processed 
   Descriptions..

Changes (04th-July-94) - 99.999% completed & ready for release!! :)


1) Changed BBS ADVERT STRIPPING so that MaxDiz Now takes information from
   A List in PFILES:  The list contains all the files that are known
   BBS Adverts.  ANY files listed here are removed from Uploads.....

2) Users can now set their personal preference as to how long MaxDiz
   Should wait before Auto-Accepting File_ID's As Descriptions.  This
   Is another Option added to the Sentby/Signature Editor.  If a User Has
   Not used the signature editor, then the SYSOp Configured Default
   TimeOut is used instead.

3) Due To A Pre Release Of MaxDiz being spread and probably installed,
   A routine as been added to Delete OLD Maxdiz Sentby Signatures if
   Detected.  /X\axDiz then informs the Users of It's actions and that
   They need to re-Edit their Signature from the main menu.

4) MaxDiz only looked for File_ID's in Archives when they had just been
   Uploaded or Adopted into Cnets Software Lists.  Now MaxDiz Also checks
   for File_ID's when Someone starts to describe Files That Have PREVIOUSLY 
   NOT BEEN DESCRIBED.

5) Fixed a bug that accured when you upload or Kill online files and then 
   use the Signature Editor...  I missed out a RETURN command on a small
   subroutine.

6) ALL ANSI Escape Codes have been removed from maxdiz's Code.  they have
   All been replaced with MCI Equivalents.  Users logging on without ANSI
   Abilities had problems when these Escape Sequences where being thrown at
   their terminals, with no hope of interpreting them properly.  CNET can
   now turn off all ANSI CODES that MaxDiz uses under these circumstances..


7) Arrived at a totally satisfactory way of elimating the inport of 
   signatures into cnets description editor.  "}" -CTRL-Q} is used as the
   first 2 characters of the signature.  This code is NEVER printed to the
   users screen and is never already present on any of the File_ID.Diz Lines
   created on the scene..  This is the way it will stay from now on.

BIG NOTE:  If you have problems when batch editing ie WR1-17 or ED1-17 then 
           Search For The Word `WAIT' in the Program code.  Adjust the Wait Time
           And retry.  I run on an A1200/030/40Mhz/FPU/35Mhz and 2.2 M/Sec Drive.
           The Wait Time Works For me Faultlessly Set At 1 Second..

Cnet Will Not Allow <CTRL-Q> to be saved in descriptions.  This code is required
To Allow an MCI Command to be stored.  The only way round this problem was to
Write Protect the _Edbuff<port> (TextEdBuffer) so that Cnet Cannot change the 
Contents of the _Edbuff when saving.  This HAS to be deleted By 'Delete FORCE'
before the next file is to be edited.  THE WAIT COMMAND is there to time this 
deletion so that it operates AFTER Cnet Has safely SAVED the _EDbuff...

This File_ID Processor and all it's functions are all contained in one

You can now edit any Descriptions on Cnet right on up to 250 lines!!  Hmmm
Is this an <Overkill Elert>>!!  This also goes for normal Files that don't 
contain File_ID.DIZ descriptions.

Cnet Cannot Handle more than 8 lines for descriptions, So A cheat was called for.
All BIG descriptions are stored as seperate files in New 'DESCS' Directory.
Cnet is forced to display them By Adding A One Line MCI Command String into Cnet's
Normal Limited 8 Line Description Editor;  ie *0 <Filename.Dsc>} - This simply 
commands cnet to AsciiSend A Description Stored Elsewhere on The Hard Drive.

If you Edit A Description & make it bigger Than 8 Lines, /X\axDiz Will move this
BIG Description into the 'DESCS' Directory and save an (AsciiSend MCI Command) to
Cnet's Description Editor. 

Alternatively,  If you have a big description and edit it down to 8 lines or less,
then /X\axDiz deletes the Description Stored in the 'DESCS' Directory and just
adds it into Cnet's Normal Description Envoiroment.  This stops the inevitable 
build-up of Obsolete Description files.

/X\axDiz Grabs the File_ID.Diz files that all other File_ID Processors grab, Plus
there is an addition enabling /X\axDiz to extract information on GIF, JPG, IFF 
and animation files.  Typically, On Uploading or Editing of a GFX File, you would
be presented with a line simular to;

<<640*425*8 ILBM Picture File>> Or <<640*425*8 60 Frame ILBM Animation File>>

The Numerics indicating - Height*Width*Bitplanes

Simple utilities can be picked up from all over the place and can be incorperated
into /X\axDiz to improve it's filetype recognition....

Colour SENTBY/Signature lines are supported with Text Centering If Required.  Once
The Sentby Line Has been Typed in the the '<' & '>' keys are used to scroll through
the colour selections...  This Idea can be expanded Greatly!!!!

Upon A user's First Completed Upload, /X\axDiz Asks For His Signature Line if
He hasn't Already Done One.  Typing 'SENT' on the Main Menu Enables The
Signature Editor...........

If A User changes his Signature and Re-Edits his Previous uploads,  his new
Signature Will Be Added To the description..  Also, if somone with Good Enough access
edit's other Users Uploads, the Uploader's New Signature will again be added to the 
description.

/X\axDiz makes use of the users Default Editor.  All Descriptions are immediately
loaded into the Users prefered Editor...

/X\axDiz's Config Allows The SYSOP to Switch off; Sentby/Signature Line Adding &
Description Editing Facilities.  The MAXIMUM lines to be used for Editing 
descriptions and the PATH where /X\axDiz is supposed to store the BIG Descriptions.
